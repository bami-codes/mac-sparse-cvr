# 연구 E 서빙: 원시 입력 → 보정 확률의 일치와 지연 (BASE, MoAE)

- 모델: 연구 E의 `train-17` 시점 체크포인트(시드 2026)와 그 고정 보정기 (iii). 보정기가 있는 체크포인트라 이 모델로 쟀다. `train-19` 모델은 구조와 텐서 크기가 같아 지연도 같을 것으로 보지만, 직접 재지는 않았다.
- 장치: Apple M4, 프로세스 안, 단일 스레드. 코드 [cvr/serving_e.py](../../cvr/serving_e.py), [scripts/serving_e.py](../../scripts/serving_e.py), 기록 `runs/e_study/serving.json`.
- 경로: 원시 행 → 공식 어휘(`df_to_dict`와 같은 조회) → 공식 텐서 배치(`MALDataset`과 같음) → 모델 → 공통 보정 (ii)·그룹별 보정 (iii). 후보별 이미지·텍스트 유사도(`mm_feat0_seq`, `mm_feat1_seq`)는 MAC에 미리 계산된 값을 읽어 넣는다. 그 계산, 네트워크, 요청 파싱, 피처 저장소 조회는 시간에 넣지 않았다.

## 일치 검사

| 모델 | 원시 확률 vs 저장된 평가 예측 | 보정 확률 vs 저장 예측에 고정 보정기를 따로 적용한 값 | 공유 인코딩 vs 후보별 인코딩 (요청 320개) | 허용 오차 |
|---|---|---|---|---|
| BASE | 1.49e-7 | 1.43e-7 | 0 | 1e-6 |
| MoAE | 1.04e-7 | 1.04e-7 | 0 | 1e-6 |

- 원시·보정 확률은 V2 2,999행(희소 그룹 1,195행 포함)을 한 행씩 넣어 비교했다.
- 공유 인코딩: 같은 요청의 후보 100개는 사용자 특성과 구매 이력이 같다. 그래서 이를 한 번만 어휘 코드로 바꾸고 후보 수만큼 펼친다(`ServerE.predict_request`). 후보마다 따로 바꾸는 경로와 결과가 정확히 같았다.

## 신규 입력의 처리 (테스트: `tests/test_pymal_run.py -k serving`)

| 입력 | 동작 | 근거 |
|---|---|---|
| 처음 보는 `user_id` | 조회하지 않는다. 결과는 기존 사용자와 같다 | 공식 모델은 `user_id` 열을 쓰지 않는다(`user_indices[:, 1:]`). 평가에서 GAUC를 묶는 데만 쓴다 |
| 어휘에 없는 값 (새 광고·상점·이력 상품) | 그 어휘의 PAD 번호(학습에 쓰인 결측값)로 바꾸고 열별로 센다(`oov`) | 학습 때 결측값과 같은 입력이다. 측정한 V2 행에서는 0건이었다 |
| 학습 통계에 없는 `ad_feat1` 그룹 | 보정기의 "미관측" 그룹 −1을 쓴다. 이 그룹의 계수는 V1의 미관측 행으로 맞췄다 | 평가 때와 같은 동작이라 서빙이 평가와 같아진다 |

## 지연 (단일 스레드, 10라운드, 두 모델과 두 경로를 번갈아 측정, ms)

같은 라운드 안에서는 같은 요청을 두 경로로 연달아 쟀다. 표의 값은 라운드별 백분위수의 중앙값이고, 괄호는 [최소, 최대]다.

| 후보 100개 요청 | 후보별 인코딩 p50 | 공유 인코딩 p50 | 후보별 인코딩 p99 | 공유 인코딩 p99 |
|---|---|---|---|---|
| BASE 전체 | 2.64 [2.42, 3.26] | **1.34** [1.29, 2.00] | 4.63 [2.65, 7.85] | 2.75 [1.44, 6.05] |
| — 인코딩 (어휘 조회·텐서 생성) | 1.72 | 0.56 | 3.07 | 0.99 |
| — 모델 | 0.83 | 0.74 | 1.46 | 1.53 |
| — 보정 | 0.05 | 0.04 | 0.21 | 0.15 |
| MoAE 전체 | 3.35 [3.29, 4.52] | **2.13** [2.08, 2.66] | 6.31 [4.68, 10.31] | 3.48 [2.34, 6.48] |
| — 인코딩 | 1.75 | 0.59 | 3.16 | 0.98 |
| — 모델 | 1.54 | 1.50 | 3.58 | 2.50 |
| — 보정 | 0.06 | 0.05 | 0.21 | 0.12 |

| 클릭 한 건 (라운드마다 1,000건) | p50 | p99 |
|---|---|---|
| BASE | 0.42 [0.40, 0.48] | 1.13 [0.50, 4.55] |
| MoAE | 0.75 [0.72, 0.88] | 2.24 [0.90, 3.49] |

- **같은 라운드 짝 비교**: 공유 인코딩은 10라운드 모두에서 p50을 줄였다(BASE 라운드별 비율 중앙값 0.53, MoAE 0.63). 인코딩 단계만 보면 약 3분의 1이 됐다. p99는 20개 짝 중 19개에서 줄었다.
- **단계별 시간은 직접 쟀다.** 후보별 경로에서 가장 큰 몫은 인코딩(BASE p50 1.72ms)이었다. 앞선 기록에서 "약 1.3ms가 어휘 조회"라고 쓴 것은 전체에서 모델 시간을 뺀 추정이었고, 텐서 생성과 보정이 섞여 있었다.
- 합성 요청: V2의 실제 행 100개의 광고·맥락 특성과 유사도 점수에, 다른 한 행의 사용자 특성과 구매 이력을 붙였다. 실제 요청 로그가 아니다. 요청은 300개이고 라운드마다 100개씩 돌아가며 쓰므로, 요청 하나가 3–4번 측정된다.
- 채택 기준(연구 C: 이 저장소의 다른 파이썬 없음, 다른 프로세스 CPU 합 400% 이하)은 20회 중 19회 통과했다.

## 절대 지연 수치를 쓰는 범위

- **p99는 이 맥에서 측정 시점마다 크게 달랐다.** 같은 코드인 후보별 경로의 BASE 요청 p99가 앞선 측정 세션에서는 2.19ms, 이번 세션에서는 4.63ms였다. 클릭 한 건 p99도 0.47ms에서 1.13ms로 달라졌다. 두 세션 모두 채택 기준을 통과했다. 이번 세션 시작 때 부하 평균은 7.3(10코어)이었고, 다른 프로세스가 CPU 272%를 쓰고 있었다. 400% 기준은 이런 차이를 막기에 느슨하다.
- p50은 두 세션에서 비슷했다(BASE 클릭 0.38 / 0.42ms). 라운드 안의 짝 비교도 일관됐다. 그래서 쓸 수 있는 것은 "단일 스레드에서 클릭 한 건 p50 약 0.4ms(BASE)와 0.75ms(MoAE)", "공유 인코딩이 후보 100개 요청의 p50을 37–48% 줄인다"까지다. 운영 하드웨어에서의 p99는 재지 않았다.
- 앞선 세션 기록은 `runs/e_study/serving_before_shared.json`, 그 전의 예비 측정은 `serving_preliminary_2.json`이다. 다른 분석 스크립트와 동시에 돌아 10라운드 중 4–5개만 채택 기준을 통과한 측정은 `serving_contaminated_3.json`으로 남겼고 쓰지 않는다.

## 읽는 법

- MoAE의 모델 계산은 BASE의 약 2배다(p50 1.50 vs 0.74ms, 공유 경로). 공유 인코딩 뒤에는 MoAE 요청 시간의 70%가 모델 계산이다. BASE는 55%다.
- MoAE를 고르는 판단에는 세 가지가 함께 들어간다. 순위 성능의 이득(`train-19` 모델의 공식 테스트 AUC +0.016), 이 계산 비용, 학습 종료 시점에 대한 민감도(§18.11)다.
- 운영 환경의 하드웨어, 배치 크기, 다중 스레드, 피처 저장소 조회 시간은 재지 않았다.
