# 연구 E 서빙: 원시 입력 → 보정 확률의 일치와 지연 (BASE, MoAE)

- 모델: 연구 E의 `train-17` 시점 체크포인트(시드 2026)와 그 고정 보정기 (iii). 보정기가 있는 체크포인트라 이 모델로 쟀다. 구조가 같으므로 `train-19` 모델의 지연도 같다.
- 장치: Apple M4, 프로세스 안, 단일 스레드. 코드 [cvr/serving_e.py](../../cvr/serving_e.py), [scripts/serving_e.py](../../scripts/serving_e.py), 기록 `runs/e_study/serving.json`.
- 경로: 원시 행 → 공식 어휘(`df_to_dict`와 같은 조회) → 공식 텐서 배치(`MALDataset`과 같음) → 모델 → 공통 보정 (ii)·그룹별 보정 (iii). 후보별 이미지·텍스트 유사도(`mm_feat0_seq`, `mm_feat1_seq`)는 MAC에 미리 계산된 값을 읽어 넣는다. 그 계산, 네트워크, 요청 파싱, 피처 저장소 조회는 시간에 넣지 않았다.

## 일치 검사 (V2 2,999행, 그중 희소 그룹 1,195행, 한 행씩)

| 모델 | 원시 확률 vs 저장된 평가 예측 | 보정 확률 vs 저장 예측에 고정 보정기를 따로 적용한 값 | 허용 오차 |
|---|---|---|---|
| BASE | 1.49e-7 | 1.43e-7 | 1e-6 |
| MoAE | 1.04e-7 | 1.04e-7 | 1e-6 |

## 지연 (10라운드, 두 모델을 번갈아 측정, 중앙값 [최소, 최대], ms)

| | BASE p50 | BASE p99 | MoAE p50 | MoAE p99 |
|---|---|---|---|---|
| 클릭 한 건 (라운드마다 1,000건) | 0.384 [0.373, 0.436] | 0.473 [0.433, 0.690] | 0.697 [0.688, 0.707] | 0.826 [0.785, 0.853] |
| 후보 100개 요청 (라운드마다 100건) | 1.948 [1.902, 2.871] | 2.194 [2.018, 3.195] | 2.720 [2.692, 3.140] | 3.020 [2.843, 3.689] |
| 같은 요청의 모델 계산만 | 0.676 [0.673, 0.679] | 0.785 [0.742, 0.860] | 1.419 [1.405, 1.423] | 1.611 [1.553, 1.683] |

- 후보 100개 요청은 V2의 실제 행 100개의 광고·맥락 특성과 유사도 점수에, 한 사용자의 특성과 구매 이력을 붙여 만든 합성 요청이다. 실제 요청 로그가 아니다.
- 요청 시간의 약 1.3ms는 원시 값을 어휘 코드로 바꾸는 파이썬 처리다. 모델 계산은 BASE 0.68ms, MoAE 1.42ms(p50)다.
- 20회 측정 모두 연구 C의 채택 기준을 통과했다(이 저장소의 다른 파이썬 없음, 다른 프로세스 CPU 합 400% 이하).
- 측정 방식에 대한 기록: 처음에는 모델마다 한 번씩 쟀다. 그런데 이 맥의 다른 프로세스(편집기가 CPU 3–4코어를 계속 사용)가 p99를 크게 흔들었다. 두 번의 예비 측정에서 BASE 클릭 p99는 0.47ms와 2.01ms였고, MoAE는 2.92ms(채택 기준 미통과)와 0.875ms였다. 그래서 두 모델을 번갈아 여러 라운드 재는 방식으로 바꿨다. 예비 측정 기록은 `runs/e_study/serving_preliminary_2.json`에 남겼다.

## 읽는 법

- 두 모델 모두 클릭 한 건 p99가 1ms 미만, 후보 100개 요청 p99가 약 2–3ms다(이 맥, 단일 스레드).
- MoAE의 모델 계산은 BASE의 약 2배다. 순위 성능의 이득(`train-19` 모델의 공식 테스트 AUC +0.016)과 이 비용, 그리고 학습 종료 시점에 대한 민감도(§18.11)를 함께 놓고 고른다.
- 운영 환경의 하드웨어, 배치 크기, 피처 저장소 조회 시간은 재지 않았다.
