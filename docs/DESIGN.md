## 0. 연구 질문과 주장 범위

- **연구 질문**: 학습 데이터가 부족한 그룹에서 구매 이력과 상품 유사도 정보는 전환 예측에 얼마나 도움이 되고, 남는 확률 오차는 어떻게 줄일 수 있는가?
  - 1지망: 희소 그룹의 예측 성능과 확률 보정 개선, 작은 모델의 추론 시간 측정.
  - 2지망: 어떤 정보가 어느 그룹에서 도움이 되는지 제거 실험으로 분석하고, LLM이 그 결과를 근거로 다음 가설과 검증 방법을 제안.
- **데이터 선택 근거 (MAC vs CASCADE)**: 위 질문에는 구매 이력 시퀀스와 시각 유사도가 필요하고, 이 정보는 MAC에만 있다. CASCADE는 클릭·결제·환불 시각이 있어 "레이블이 늦게 확정되는 환경"을 연구하기에는 더 적합하다. 따라서 이 선택은 데이터 자체의 우열이 아니라 **연구 질문에 따른 선택**이다. §10 E6의 전제가 성립하지 않으면 다시 검토한다.
- **하려는 주장 (형태)**: "타오바오 광고 클릭 공개 벤치마크(MAC)에서, 익명 광고 특성 `ad_feat1`(카테고리로 추정) 기준 학습 표본·전환이 적은 그룹의 마지막 클릭 귀속 전환 예측은 [방법]을 썼을 때 [기준] 대비 LogLoss·보정이 [개선됐다 / 개선을 확인하지 못했다]. 불확실성은 [..]이고, 이 환경에서 단건 추론 지연은 [x] ms였다."
- **하지 않을 주장**
  - 네이버 데이터·시스템에서의 효과. "소규모 버티컬 광고 성능을 높였다".
  - `ad_feat1`이 카테고리라고 단정하는 것 (공식 매핑을 얻기 전까지).
  - 배포 시점 재현. 원래 트래픽 분포에서의 보정이나 입찰 성과.
  - 데이터 기반 귀속(DDA) 레이블을 인과 효과의 정답으로 취급하는 것.

## 1. 데이터: MAC (Multi-Attribution Benchmark)

**개요** (논문 arXiv 2603.02184, 공식 코드 PyMAL, Apache-2.0)
- `[공식]` 타오바오 광고 시스템 로그에서 추출. 21일, 광고 클릭 7,900만 건, 상품 1,510만 개, 사용자 80만 명. 한 행 = 광고 클릭 1건. 사용자 활동량에 따라 추출 비율이 다름.
- `[공식]` 레이블 4종: `last`, `first`, `linear`, `mta`(데이터 기반 귀속). 귀속 기간은 비공개.
- `[공식]` 파일: `train-00`~`train-19`(각 2.6–3.3GB), `test`(3.2GB), `vocabs/`. 공식 코드는 학습 파일을 00 → 19 순서로 학습한 뒤 테스트로 평가한다.
- `[추정]` 학습 파일 1개 = 하루. 파일 수(20 + 1)가 21일과 일치한다는 정황만 있다. E4에서 보조 점검한다.

**컬럼 의미**

| 컬럼 | 근거 | 이 문서에서의 표기 |
|---|---|---|
| `ad_feat0`, `ad_feat1`, `ad_feat2` | `[공식]` 논문: 행동 시퀀스 원소는 상품·상점·카테고리 ID. 코드: `ad_feat0~2_seq`가 `ad_feat0~2`의 어휘로 매핑됨 → 세 컬럼이 {상품, 상점, 카테고리}에 대응한다는 데까지는 공식 자료로 뒷받침. **어느 것이 무엇인지는 매핑 없음** | `[추정]` 고유값 수로 `ad_feat0` = 상품, `ad_feat1` = 카테고리, `ad_feat2` = 상점. 학습 파일 기준으로 E2에서 다시 점검 |
| `ad_feat3~5`, `context_feat0~3`, `user_feat0~5` | `[공식]` 상품·맥락·사용자 특성이라는 것까지만. 논문의 "광고 시나리오 ID"가 어느 컬럼인지는 없음 | `[미확인]` |
| `mm_feat0_seq`, `mm_feat1_seq` | `[공식]` 논문: 시퀀스 원소마다 타깃 상품과의 시각적 유사도 점수 (논문은 1개, 데이터는 2개 컬럼) | `[미확인]` 두 컬럼의 차이 |

- **결과 문장 규칙**: "카테고리"가 아니라 "`ad_feat1`(카테고리로 추정되는 익명 광고 특성)"으로 쓴다.
- **테스트 파일 열람 기록 (투명성)**: v0.3 작성 전에 테스트 파일의 스키마, 한 row group의 고유값 수와 레이블 평균을 봤다. 이후 그룹 정의, 임계값, 레이블 결정에는 테스트를 쓰지 않는다.
- **처리 방식**: 필요한 열만 선택하고, 16진 문자열 ID는 정수 코드로 변환하고, 파일 단위로 처리한다. 공식 코드는 CUDA가 고정되어 있고 파일 전체를 pandas로 읽기 때문에 그대로 쓰지 않고 참고만 한다.

**보조 데이터 (선택, 마감 후)**
- CriteoPrivateAd: 클릭 → 랜딩 → 방문 → 구매 단계별 분석이 필요할 때만 쓴다. 구매 레이블은 논문 정의 `(is_visit == 1) & (nb_sales.fillna(0) > 0)`를 따른다.
- Criteo Uplift / CRITEO-ITE: 2지망 인과 추정 검증용 (부록).

## 2. 예측 대상과 입력

- **y** = `(last > 0)`, 즉 **마지막 클릭 귀속 기준의 전환 양성 여부**. 다른 귀속 방식의 양성 비율이나 성능과 섞어 비교하지 않는다.
- **입력 금지**: `first`, `linear`, `mta`, `last`. 다른 귀속 레이블은 확장 실험에서 **보조 학습 정답으로만** 쓴다.
- **입력 사용**: 사용자·상품·맥락 특성과 행동 시퀀스. 시퀀스는 클릭 이전의 구매 이력이므로 클릭 시점 입력으로 본다 (공식 모델도 입력으로 사용).
- **시퀀스 파생 피처 (M1·M2용)**: 타깃 `ad_feat1`이 구매 시퀀스에 나온 횟수, 타깃 `ad_feat2`가 나온 횟수, 타깃 상품 재등장 여부, `mm` 점수의 최댓값·평균. 2지망 단서 분석에도 그대로 쓴다.

## 3. 희소 그룹 정의

- **G1 (주)**: `ad_feat1` 값별 그룹. **주 정의**: 학습 구간 양성 수 < c_min 이면서 학습 구간 클릭 수 ≥ n_min. **민감도 분석**: 분위수 기준.
- **G2 (보조)**: `ad_feat2` 값별 같은 방식.
- **신규 값**: 학습 구간에 없던 값은 별도 집단으로 집계한다.
- **S. 통제 희소화**: 큰 G1 그룹 k개의 학습 표본만 {1, 5, 20, 100}%로 줄이고, 검증·테스트는 고정한다. 추출 시드는 5개 이상. 해석: "같은 그룹에서 학습 표본 수를 줄였을 때의 변화".
- **결정 규칙**: 임계값과 그룹 목록은 학습 구간 통계로만 정한다.

## 4. 분할

| 구간 | 파일 (초안) | 용도 |
|---|---|---|
| 학습 | `train-12`~`train-17` (6개; 처리 가능성을 보고 늘림) | 모델 학습, 그룹 통계 |
| 검증 V1 | `train-18` | 보정 파라미터 학습 |
| 검증 V2 | `train-19` | 모델·보정 방식·축소 강도 선택 |
| 테스트 | `test` | 모든 설정을 고정한 뒤 **1회만** 실행 |

- 파일 순서는 `[추정]`이다. 순서가 틀려도 학습·검증·테스트가 서로 다른 파일이라는 점은 유지된다.
- `train-10`, `train-11`은 2지망 확증 전용으로 남겨 두고 1지망에서는 쓰지 않는다 (부록).
- **처리 순서**: 학습 파일 하나의 부분자료로 처리 시간, 최대 메모리, 평가 코드가 정상인지 먼저 확인하고, 그 결과를 보고 필요한 파일만 순차적으로 받는다. 학습 파일 6개는 상한이지 필수가 아니다.
- **해석 범위**: 귀속 기간이 비공개라서 "당시 확보 가능한 레이블만으로 학습한 배포 상황"은 재현하지 못한다. 모든 결과는 **"공개 벤치마크의 확정된 귀속 레이블을 이용한 오프라인 비교"**로 설명한다.
- **보정 결과의 범위**: 사용자 활동량별 추출이 있으므로 "이 표본 분포에서의 보정"으로만 말한다. 근거 없는 재가중은 하지 않는다.

## 5. 비교 모델

| ID | 모델 | 상태 |
|---|---|---|
| M0a | `ad_feat1`별 CVR을 전체 평균으로 평활 (베타-이항, 경험적 베이즈) | 필수 |
| M0b | `ad_feat2`별 CVR을 전체 평균으로 평활 | 필수 |
| M1 | 로지스틱 회귀 + 해시 피처 + 시퀀스 파생 피처 | 필수 |
| M2 | LightGBM (같은 피처) | 필수 |
| M5 | 사후 보정 비교: (i) 보정 전 → (ii) 전체 공통 보정 → (iii) G1 그룹별 보정을 (ii) 쪽으로 축소 / (iv) `logit(p)`와 `log(1 + 학습 그룹 클릭 수)`를 입력으로 받는 작은 공통 보정 모델 | 필수 |
| M6 | 같은 작은 신경망에서 보조 귀속 레이블 학습 유무 비교 (MAC 논문 방향) | 여력이 있으면 |
| M3 / M4 | DNN / 멀티도메인 | 확장 |

- **M5**: 기반 모델은 V2에서 고르고 테스트 전에 고정한다. 보정은 V1에서 학습하고 방식과 축소 강도는 V2에서 고른다. 형태는 `logit(p') = a_g·logit(p) + b_g` (단 `a_g > 0`), 공통 값 쪽으로 L2 벌점을 준다. `a_g > 0`인 그룹별 단조 보정은 **그룹 내 AUC를 바꾸지 않으므로** 순위 구분력 개선은 주장하지 않는다.
- **M6 주의**: 다중 귀속 학습은 다중 도메인 학습과 다른 문제다. M6을 했다고 희소 그룹 개선이 검증되지는 않는다.

## 6. 평가

- **1차 지표**: G1 희소 그룹별 테스트 LogLoss의 **동일 가중 평균** (macro).
- **보조 지표**: 전체 LogLoss·AUC, G1 클릭 가중 LogLoss, 그룹 내 AUC의 macro 평균, 그룹별 보정, G2 결과.
- **보정 지표**: 그룹별 (예측 합 / 실제 양성 합). 양성이 0인 그룹은 비율 대신 (예측 합 − 실제 합)과 해당 그룹 수를 보고한다. ECE는 등빈도 10구간.
- **AUC 예외**: 한 종류 레이블만 있는 그룹은 AUC macro에서 빼고, 뺀 그룹 수를 보고한다.
- **불확실성**: paired bootstrap (같은 재표집 표본에서 두 모델의 차이), B = 1000, 재표집 단위는 `user_id` 클러스터 (민감도: 클릭 단위), 95% 백분위 구간.
- **시드**: 기반 모델 학습 시드 3개, S축 추출 시드 5개.
- **지연**: 원시 입력 1건 → 전처리 → 예측 → 보정까지, 같은 프로세스 안에서 측정 (네트워크·피처 저장소 조회 제외). Apple M4, 단일 스레드. **목표: batch=1 p99 ≤ 1 ms.** batch=100도 보고하고, 목표를 못 맞추면 그대로 보고한다.

## 7. 성공 기준 (테스트 실행 전에 고정)

1. **1차**: V2의 1차 지표로 (iii)와 (iv) 중 하나를 고른다. 테스트에서는 **선택된 방식 vs (ii)**를 한 번만 비교한다. 선택된 방식의 1차 지표가 더 좋고, paired bootstrap 95% CI가 0을 포함하지 않으며, 기반 모델 시드 3개에서 모두 같은 방향이면 충족이다. 선택되지 않은 방식과 (ii) vs (i)(보정 자체의 효과)는 보조 결과로 보고한다.
2. **2차**: 전체 AUC 하락 ≤ 0.002 (**이 프로젝트의 임시 기준**). 그룹별 |1 − 보정 비율|이 줄어든다.
3. **지연**: §6 목표.
4. **테스트 전 고정 항목**: 학습 파일 범위, 기반 모델, 그룹 목록, 임계값, 축소 강도, 평가 코드의 커밋 해시.

## 9. 재현성과 검토 절차

- 원본 데이터는 레포에 넣지 않고 파일별 체크섬만 기록한다. `uv` lock 파일, 설정 파일, 시드를 고정하고, 명령 하나로 각 실험을 재실행할 수 있게 한다. 결과 표마다 실행 로그와 커밋 해시를 남긴다.
- **흐름**: 설계 검토 → 작은 단위 구현 → 고정 커밋 해시 기준 리뷰 → 수정 → 재검증.

- `REVIEW.md`에는 사용자가 직접 코드에서 확인하고 이유를 설명할 수 있는 항목만 기록한다.

## 10. EDA (학습 파일 일부로만)

- **E1**: 파일별 행 수, 4개 귀속 레이블의 분포와 `last > 0` 비율, 처리 시 최대 메모리
- **E2**: 컬럼 관계 점검. `ad_feat0` → `ad_feat1`, `ad_feat0` → `ad_feat2`가 함수 종속인지, `ad_feat1` → `ad_feat3`이 상위 분류 관계인지 등. 결과는 **추정을 뒷받침하거나 반박하는 근거로만** 기록하고, 의미를 증명했다고 쓰지 않는다
- **E3**: 학습 구간의 G1·G2 그룹별 클릭·양성 분포 → c_min, n_min 후보
- **E4**: 파일 순서 보조 점검 (인접 파일 간 사용자·상품 겹침이 더 높은지)
- **E5**: 시퀀스 길이와 결측, `mm` 점수 분포
- **E6 (MAC 선택 전제 점검, `train-17`의 학습용 부분자료로만)**: 아래 세 가지가 성립하지 않으면 데이터 선택을 다시 검토한다.
  1. 평가 가능한 희소 그룹이 충분하다. 즉 `ad_feat1` 그룹 중 클릭 수 ≥ n_min이면서 양성 수가 적은 그룹이 수십 개 이상 있다.
  2. 구매 이력 정보가 실재한다. 타깃과 같은 `ad_feat1`·`ad_feat2` 값이 구매 시퀀스에 나오는 클릭 비율이 0에 가깝지 않고, 그 여부에 따라 양성 비율이 다르다.
  3. 희소 그룹에 남는 확률 오차가 있다. 전체 공통 모델의 그룹별 (예측 합 / 실제 합)이 희소 그룹에서 더 크게 벗어난다.

### 10.2 점검 결과에 따른 설계 변경 (리뷰 반영, 확정)

1. **패딩·결측 처리**: `dbee74ee5fbf`를 결측으로 다룬다. 구매 이력 일치 횟수에서 제외한다. `ad_feat1`이 이 토큰인 행은 삭제하지 않고 "결측" 집단으로 따로 보고하며, G1 희소 그룹 정의에서는 뺀다.
2. **M5(iv)를 비교 후보로 추가**: `logit(p)`와 `log(1 + 학습 그룹 클릭 수)`를 입력으로 받는 작은 공통 보정 모델. V1에서 학습하고 V2에서 선택한다. (iii) 그룹별 축소 보정을 대체하거나 더 낫다고 전제하지 않는다. 후보가 늘었으므로 §7 성공 기준을 함께 갱신했다.
3. **재현성**: LightGBM은 `deterministic=True`, `force_row_wise=True`로 고정한다. polars의 `Categorical` 변환은 실행마다 코드가 달라져 결과가 바뀌는 것을 확인했으므로 쓰지 않는다. 고친 뒤 두 번 실행한 결과 모델 지표는 동일했고, 그룹 집계는 상대 오차 5×10⁻¹⁶ 이내였다.
4. **공통 범주형 매핑**: 지금의 파일별 정렬 순위 코드는 파일 하나 안의 점검에만 맞다. 파일마다 따로 순위를 매기면 같은 숫자가 다른 범주를 뜻하게 된다. 본 실험에서는 **학습 파일로 만든 매핑을 저장해 검증·테스트에도 그대로 적용**하고, 학습에 없던 값은 "미등록" 코드 하나로 보낸다. LightGBM에는 NumPy 배열이 넘어가므로 범주 이름에 따른 자동 정렬을 기대하지 않는다.
5. **메모리**: 파일 하나에 최대 14GB가 든다. 여러 파일을 한꺼번에 올리지 않고, 파일마다 공통 매핑으로 숫자 피처 행렬을 만들어 저장한 뒤(파생 데이터, 레포 미포함) 학습에 합친다.
6. **임계값**: c_min, n_min은 학습 범위를 정한 뒤 학습 통계로 확정한다. 파일 수에 기계적으로 비례시키지 않는다.

## 12. 결정 기록

- 주 데이터: MAC (1·2지망 공통). 근거는 §0의 연구 질문. PrivateAd와 Criteo Uplift는 선택 확장. CASCADE는 후속 실험 후보로, 쓰게 되면 "다른 데이터와 시간 조건에서도 방법이 유효한가"를 보는 것이다 (MAC에 시간 정보만 더한 동일 조건 비교가 아님).
- 2지망 필수 범위: 귀속 방식 4종 비교는 확장이다. 구매 이력 특성의 유용성, 희소 그룹 보정, 추론 시간이 중심이다.
- 주 레이블: `last > 0`.
- 마감 전 범위: M0a·M0b·M1·M2·M5. M6은 여력이 있을 때.
- 1차 지표: G1 희소 그룹별 LogLoss의 동일 가중 평균.
- **남은 결정**: c_min·n_min과 학습 파일 범위 (E1–E3 후), 지연 목표 1 ms의 적절성.

| 인과 추정 검증 | — | Criteo Uplift: 처치 = 타게팅 허용 여부 (노출 아님), 별도 표본에서 uplift 순위·정책 성과·평균 효과와 CI. CRITEO-ITE(원 논문 정의의 반합성 데이터)로 추정 오차와 CI 포함률 |

- **확증 파일 사전 지정**: `train-10`, `train-11`은 2지망 확증 전용이다. 1지망과 2지망 가설 발굴 단계에서는 열지 않는다. 확증 실험의 모델은 그보다 앞선 파일(예: `train-05`~`09`)로 학습한다. 이미 결과를 반복해서 본 파일을 독립 검증 자료로 취급하지 않는다. 다만 두 파일을 남겨 두었다는 사실만으로 미래 시점 검증이나 통계적 독립성이 보장되지는 않는다. 파일 순서(E4)와 발굴 파일과의 사용자 중복을 확인하고, 확인한 범위에 맞게 설명한다.
- **프로토타입 평가 기준**: 근거 없는 수치를 만들지 않는가, 실제로 실행 가능한 실험을 제안하는가, 인과적 주장에 "현재 데이터로 검증 불가"를 표시하는가. "검증 불가"도 정상 출력이다.
- **인과 추론 (우대 사항, 선택)**: 인과 효과는 무작위 실험 데이터나, 식별 가정이 갖춰진 관측 연구 설계로 추정할 수 있다. 합성·반합성 데이터는 정답 효과를 알고 **추정 방법을 평가할 때** 쓴다. 시간이 되면 Criteo Uplift(실제 실험)와 CRITEO-ITE(반합성)를 다룬다. 이번 프로젝트에서 필수는 아니다.
