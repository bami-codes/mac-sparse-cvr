# 전환이 드문 광고 그룹을 위한 CVR 예측과 저지연 후보 점수화

[![CI](https://github.com/bami-codes/mac-sparse-cvr/actions/workflows/ci.yml/badge.svg)](https://github.com/bami-codes/mac-sparse-cvr/actions/workflows/ci.yml)

광고 전환율(CVR) 모델의 확률은 클릭은 많아도 전환이 드문 광고 그룹에서 쉽게 어긋난다. 이 저장소는 Alimama의 공개 데이터셋 [MAC](https://huggingface.co/datasets/alimamaTech/MAC)([논문](https://arxiv.org/abs/2603.02184))과 논문의 공식 모델로 세 가지를 한다. 공식 모델을 전체 규모로 재현하고, 전환이 드문 그룹의 확률 오차를 재서 보정하고, 한 사용자의 광고 후보 100개를 CPU 코어 하나로 수 ms 안에 점수화하는 예측기를 만든다.

## 한눈에

- **재현**: 공식 코드를 고치지 않고 BASE·MoAE를 전체 학습 자료로 학습했다. AUC·GAUC 네 값이 모두 논문 표 4와 0.0032 안이다(사전 기준으로 재현 1개, 근접 3개).
- **확률**: 원시 확률은 전체적으로 낮았다. MoAE의 관측/예측 비(O/E)는 전체 1.247, 희소 그룹 1.338이었고, 공통 보정 하나로 0.976, 0.987이 됐다. 희소 그룹만의 몫은 작았다. 그룹별 보정의 추가 이득도 작지만 확인됐다(희소 그룹 LogLoss −0.000011 [−0.000019, −0.000004]).
- **모델 선택**: 학습을 두 파일 더 하자 MoAE와 BASE의 순위가 뒤집혔다(`train-17` → `train-19`, MoAE − BASE AUC −0.019 → +0.016).
- **서빙**: 후보 100개 요청을 Linux 서버의 CPU 코어 하나에서 BASE p50 1.89ms·p99 3.21ms, MoAE 3.98ms·5.64ms에 점수화한다. 사용자 이력을 요청마다 한 번만 인코딩해 p50을 34%·20% 줄였다.

**권고**: 마지막 두 학습 파일을 보정용으로 남길 수 있다면 **BASE + 그룹별 축소 보정**을 쓴다. 검증 자료와 공식 테스트 모두에서 BASE가 순위와 희소 그룹 손실이 나았고, 더 빨랐다. 학습 파일을 모두 쓰면 MoAE가 순위에서 앞서지만, 그때는 보정을 맞출 자료가 남지 않아 확률 품질을 평가하지 못했다. 두 조건 중 무엇이 나은지는 여러 기간에서 재학습 주기를 비교해야 정할 수 있다.

## 써 보기

```bash
uv sync
uv run python -m cvr.predictor examples/request.json
```

```json
{
  "model": "BASE",
  "calibration": "group-shrunk Platt on the ad group (ad_feat1)",
  "candidates": [
    {"ad_feat0": "bd06e0d08ba7", "ad_feat1": "707e766d45eb", "cvr": 0.0365, "cvr_uncalibrated": 0.0332},
    {"ad_feat0": "db402f022dcf", "ad_feat1": "76af7efae0d0", "cvr": 0.0133, "cvr_uncalibrated": 0.0177},
    {"ad_feat0": "ca752f48f687", "ad_feat1": "76dc15e364ed", "cvr": 0.0224, "cvr_uncalibrated": 0.0268}
  ],
  "values_not_in_vocabulary": {}
}
```

**요청과 응답**

- 요청은 MAC의 원시 열로 쓴다. 사용자 특성, 구매 이력 3열, 후보마다 광고·맥락 특성과 이력 상품별 유사도가 들어간다.
- 사용자 이력은 요청마다 한 번만 인코딩한다.
- 어휘에 없는 값은 학습 때의 결측값으로 처리하고, 응답에 열별 개수를 돌려준다.
- `--jsonl`을 주면 모델을 한 번 띄운 채 한 줄에 요청 하나씩 받는다.

**예제 모델과 실제 모델**

- [examples/model](examples/model)은 합성 자료로 공식 학습 코드를 그대로 돌려 만든 1.3MB짜리 모델이다([scripts/make_example_bundle.py](scripts/make_example_bundle.py)). 그래서 확률 값 자체는 MAC과 관계가 없다.
- 실제 모델도 같은 명령에 모델 폴더와 어휘만 바꿔 쓴다. 다만 학습 산출물이 먼저 있어야 한다. 체크포인트(개당 2GB)와 실행 기록, 보정기이고, 크기 때문에 저장소에 넣지 않았다. 학습 명령은 [docs/reproduce.md](docs/reproduce.md)에 있다.

```bash
python3 scripts/fetch_mac.py vocabs train/train-19.parquet                       # 어휘(873MB)와 자료 한 파일
uv run python -m cvr.predictor export BASE_lr0.003_lam0.3_s2026 bundles/BASE_train17
uv run python -m cvr.predictor request-from data/raw/mac/train/train-19.parquet 123456 --candidates 100 > request.json
uv run python -m cvr.predictor request.json --bundle bundles/BASE_train17 --vocabs data/raw/mac/vocabs
```

- 실행 id의 `lam0.3`은 공식 실행 예제(`scripts/run.sh`)가 BASE에 넘기는 λ 값이다. BASE는 보조 손실이 없어 이 값을 쓰지 않는다.
- `request-from`은 실제 MAC 행으로 예시 요청을 만든다. 한 사용자의 클릭 행들을 후보로 묶는 방식이라, 행마다 광고 맥락이 다를 수 있다. 실제 요청 로그는 아니다.
- 보정기는 그 보정기를 맞춘 체크포인트(`train-17`)에만 묶인다. 다른 체크포인트(`--after train-19.parquet`)는 `--no-calibration`으로 내보내야 하고, 그러면 원시 확률만 낸다.

## 용어

| 용어 | 뜻 |
|---|---|
| 레이블 | 마지막 클릭 귀속 전환 여부(`last > 0`). MAC의 기본 레이블이다. |
| BASE / MoAE | MAC 논문의 기준 모델과 제안 모델이다. BASE는 마지막 클릭 레이블 하나로 학습한다. MoAE는 첫 클릭·선형·데이터 기반(`mta`) 귀속 레이블과 네 레이블의 조합(16가지)을 보조 과제로 함께 학습하고, 공유 전문가와 레이블별 전문가를 레이블마다 게이트로 섞는다. MoAE의 λ는 보조 손실의 가중치다. |
| 희소 그룹 (G1) | 학습 자료(`train-00`~`17`)에서 클릭이 3,069건 이상인데 양성이 123건 미만인 광고 그룹(`ad_feat1`) 979개다. 임계값은 앞선 실험의 500건·20건을 학습 행 수 비율만큼 늘린 값이다. `ad_feat1`은 카테고리로 추정되는 익명 특성이라 실제 업종과의 대응은 알 수 없다. |
| 비교 집단 (C) | 같은 클릭 조건에서 양성이 123건 이상인 그룹 1,613개다. |
| O/E | 관측 양성 수 ÷ 예측 확률의 합이다. 1보다 크면 과소 예측이다. |
| GAUC | 사용자별 AUC를 사용자의 클릭 수로 가중 평균한 값이다(MAC의 정의). |
| 공통 보정 (ii) | 모든 클릭에 같은 Platt 보정(로짓의 기울기와 절편)을 쓴다. |
| 그룹별 축소 보정 (iii) | 그룹마다 기울기와 절편을 따로 두되, 강도 λ의 벌점으로 공통 보정 쪽으로 당긴다. 이 λ는 MoAE의 λ와 다른 값이다. |
| V1 / V2 | 보정을 맞추는 파일(`train-18`)과 설정·강도를 고르는 파일(`train-19`)이다. |

## 검증 절차

1. 판정 기준을 결과 전에 적어 커밋한다([docs/DESIGN.md](docs/DESIGN.md)).
2. 설정과 보정 강도는 V1·V2에서만 고른다.
3. 모델, 보정기, 그룹 목록을 해시로 고정한다.
4. 같은 평가 코드로 V2를 다시 계산한다. 기록한 V2 값 407개를 1e-9 안에서 재현해야 다음 단계로 간다.
5. 질문마다 공식 테스트(406만 클릭)를 한 번만 연다.

- 공식 테스트는 앞선 실험에서 다른 모델로 한 번 평가한 파일이다. 그래서 결과는 "벤치마크 공식 테스트 기준"이고, 처음 보는 자료에서의 확증은 아니다.
- 구간은 사용자 단위 부트스트랩 95% 구간이고, 시드는 3개다.

## 결과

### 어떤 모델을 쓰는가

| 학습 범위 | 선택 | 근거 |
|---|---|---|
| `train-17`까지 (마지막 두 파일을 보정 적합과 강도 선택에 씀) | **BASE + 그룹별 축소 보정** | V2에서 AUC 0.849 vs MoAE 0.847, GAUC 0.743 vs 0.742, 희소 그룹 LogLoss 0.06270 vs 0.06294. 공식 테스트에서도 AUC 0.848 vs 0.829, 희소 그룹 LogLoss 0.06248 vs 0.06473. 후보 100개 요청은 BASE가 p50 1.89·p99 3.21ms, MoAE가 3.98·5.64ms다. |
| `train-19`까지 (모든 학습 파일) | MoAE가 순위에서 앞섬 | 공식 테스트 AUC 0.867 vs 0.851. 이 조건에서는 보정을 맞출 자료가 남지 않아 확률 보정의 효과는 평가하지 못했다. |

같은 테스트 클릭에서 마지막 학습 파일만 바꿨는데 두 모델의 순위가 뒤집혔다(MoAE − BASE AUC −0.019 → +0.016). 한 시점의 비교로 모델을 고르면 위험하다는 뜻이다. 같은 학습 실행의 인접한 두 시점이라 독립된 반복은 아니다.

### 재현 (논문 표 4, 공식 테스트, 시드 3개 평균)

| 모델 | AUC | 논문 | 판정 | GAUC | 논문 | 판정 |
|---|---|---|---|---|---|---|
| BASE | 0.8514 | 0.8494 | 근접 | 0.7419 | 0.7424 | 재현 |
| MoAE | 0.8674 | 0.8694 | 근접 | 0.7604 | 0.7636 | 근접 |

- 판정 기준은 테스트 전에 정했다. |차이| ≤ 0.002이면 재현, ≤ 0.005이면 근접이다.
- 두 AUC는 재현 기준을 0.0000091(BASE)과 0.0000496(MoAE) 넘었다. 시드 표준편차(BASE 0.0020, MoAE 0.0010)보다 훨씬 작은 양이다.
- MoAE − BASE는 AUC +0.0159, GAUC +0.0186이다. 논문(+0.0200, +0.0212)과 순서가 같고, 크기는 약 80–88%다.
- 설정은 논문의 탐색 범위에서 골랐다(MoAE 학습률 9개 × λ 4개, BASE 학습률 9개). 고른 값은 MoAE 학습률 0.004·λ 0.2, BASE 학습률 0.003이다.
- 공식 저장소의 실행 예제(`scripts/run.sh`)는 `--learning_rate 4.0e-3`을 넘긴다. 하지만 파서는 `--lr`만 정의하고 모르는 인자를 `parse_known_args`로 버린다. 그래서 예제는 의도한 0.004가 아니라 기본값 0.003으로 학습된다. 이 저장소의 실행기는 알 수 없는 인자를 오류로 처리한다.

### 확률 (`train-17` 모델, 공식 테스트, 시드 3개 평균)

| 모델 | 보정 | 전체 O/E | 희소 그룹 O/E | 희소 그룹 macro LogLoss |
|---|---|---|---|---|
| MoAE | 보정 전 | 1.247 | 1.338 | 0.066216 |
| | 공통 보정 | 0.976 | 0.987 | 0.064743 |
| | 그룹별 축소 보정 | 0.986 | 0.988 | 0.064731 |
| BASE | 보정 전 | 1.118 | 1.139 | 0.062602 |
| | 공통 보정 | 0.973 | 0.972 | 0.062493 |
| | 그룹별 축소 보정 | 0.979 | 0.972 | 0.062482 |

- **오차의 대부분은 전체 수준이었다.** MoAE의 예측 합계는 전체 클릭에서 관측 전환보다 약 20% 적었고(O/E 1.247), 희소 그룹에서는 약 25% 적었다(1.338). V2에서도 전체 O/E가 1.245였다. BASE도 같은 방향이지만 덜 어긋났다(1.118). 원인은 분리하지 않았다.
- **그래서 공통 보정이 먼저다.** 공통 보정 하나로 MoAE의 희소 그룹 macro LogLoss가 0.00147 낮아졌다.
- **그룹별 축소 보정은 작지만 확인된 추가 이득이다.** MoAE의 희소 그룹 LogLoss가 −0.000011 [−0.000019, −0.000004] 낮아졌고, 시드 3쌍 모두 같은 방향이었다. BASE도 −0.000011 [−0.000018, −0.000005]였다.
  - 그룹별로 보면 MoAE에서 548개가 좋아지고 431개가 나빠졌다. 운영에 쓴다면 그룹별 O/E를 지켜봐야 한다.
  - 앞선 LightGBM 실험에서도 그룹별 보정으로 개선됐고, 개선 폭은 그쪽이 더 컸다(−0.000100 [−0.000154, −0.000049], 희소 그룹 1,083개). 다만 학습량과 그룹 구성이 달라 차이의 원인은 분리하지 못했다.
- **학습 단계에서 희소 그룹을 2배로 가중하는 방법은 확인되지 않았다.** 차이는 −0.000069 [−0.000231, +0.000088]이고, 시드마다 방향이 달랐다.

### 서빙 (Linux 서버, AMD EPYC 4565P 코어 하나, 세 세션의 중앙값)

| 모델 | 요청 (후보 100개) p50 | p99 | 클릭 한 건 p50 | 사용자 공유 인코딩의 단축 (p50) |
|---|---|---|---|---|
| BASE | 1.89ms | 3.21ms | 0.40ms | 34% |
| MoAE | 3.98ms | 5.64ms | 0.71ms | 20% |

- 서빙한 확률은 평가에 쓴 예측과 같다. 같은 배치 경로로 비교하면 차이는 2.1e-7 이내다. 평가 예측은 다른 CPU에서 배치로 계산했기 때문에, 서버에서 한 행씩 계산하면 float32 반올림이 달라져 최대 1.8e-6까지 차이 난다(허용 오차 1e-5).
- 같은 사용자의 구매 이력을 후보마다 다시 인코딩하지 않으면 확률은 그대로이고 시간만 준다.
- 세션마다 모델별로 요청 6,000개(두 경로에 3,000개씩)를 쟀다. 모든 값이 세 세션 사이에서 1.16배 안이다.
- 네트워크, 요청 파싱, 피처 저장소 조회는 시간에 넣지 않았다. 유사도는 MAC에 미리 계산된 값을 쓴다.

## 지표마다 결정이 달라진다

광고 CVR은 쓰는 곳마다 보는 지표가 다르다. 입찰은 클릭 한 건의 확률을 쓰고, 노출 순서는 순위를, 성과 예측은 그룹 합계를 쓴다. 이 저장소의 실험에서 같은 선택이 지표에 따라 달라졌다.

- **순위와 확률은 다른 문제였다** (위 결과):
  - 마지막 학습 파일만 바꿔도 MoAE − BASE의 AUC가 뒤집혔다.
  - 반면 확률의 수준은 공통 보정 하나로 대부분 맞춰졌다.
  - 순위는 모델이, 확률의 수준은 보정이 좌우했다.
- **그룹별 보정은 그룹 평균을 좋게 하면서 합계를 흔들었다** (작은 광고 맥락 그룹 22개, 도메인 절편을 둔 LightGBM 모델 G-int, 이미 연 평가 파일을 다시 쓴 [백테스트](docs/results/study_d.md)):

  | 그룹별 보정 (λ = 1) − 공통 보정 | 차이 [95% 구간] |
  |---|---|
  | 그룹을 같은 비중으로 본 LogLoss | −0.000147 [−0.000253, −0.000054] (나아짐) |
  | 클릭을 같은 비중으로 본 LogLoss | −0.000003 [−0.000036, +0.000028] (차이 불분명) |
  | 그룹별 양성 클릭 수의 Poisson deviance | +1.80 [+0.41, +3.16] (나빠짐, 시드 3쌍 모두) |

  첫 줄은 [연구 C의 테스트](docs/results/c_final_test.md)에서 처음 기록한 비교와 같다. 부트스트랩을 따로 돌려 그쪽 구간은 [−0.000256, −0.000052]다.
- **보정 강도를 고르는 지표가 강도를 바꿨다** (같은 모델, 같은 그룹):
  - LogLoss로 고르면 λ = 1이다. 이때 그룹 평균 LogLoss 0.037947, 그룹 합계 deviance 3.755, O/E 0.950이다.
  - 그룹 합계로 고르면 λ = 10000이다. 이때 각각 0.038092, 1.903, 1.001이다.
- **정리**: 보정 후보는 실제로 쓸 곳의 지표로 함께 비교하고, 공통 보정도 후보에 둔다. 입찰에 쓸 확률과 예상 성과에 쓸 합계는 같은 모델에서도 다른 보정을 고를 수 있다.

## 앞선 실험

같은 데이터에서 LightGBM과 작은 신경망으로 먼저 한 실험들이다. 위 결과의 출발점이다.

- **1차 실험, LightGBM 희소 그룹 보정** (공식 테스트): 그룹별 축소 보정 −0.000100, 확인됨. [결과](docs/results/final_test.md)
- **2차 실험, 보조 귀속 레이블(`mta`)과 그룹 전환율 입력** (`train-12`): −0.000145 [−0.000292, +0.000010], 확인되지 않음. [결과](docs/results/p2_final_test.md)
- **연구 C, 작은 광고 맥락 그룹의 도메인 구조** (GBDT·신경망 7종, `train-13`·`14`): 공유 구조와 그룹별 절편의 차이가 확인되지 않았다. 클릭 단위 손실과 그룹 합계 오차가 서로 다른 방향으로 움직였다. [결과](docs/results/c_final_test.md)
