# 전환이 드문 광고 그룹의 CVR 예측과 ms 단위 후보 점수화

[![CI](https://github.com/bami-codes/mac-sparse-cvr/actions/workflows/ci.yml/badge.svg)](https://github.com/bami-codes/mac-sparse-cvr/actions/workflows/ci.yml)

클릭은 많은데 전환이 거의 없는 광고 그룹에서는 CVR 모델의 확률이 쉽게 어긋납니다. 입찰은 이 확률을 그대로 쓰기 때문에 순위만 맞아서는 부족합니다. 소규모 버티컬처럼 전환 표본이 적은 광고가 이런 처지에 놓입니다.

이 저장소는 Alimama의 공개 데이터셋 [MAC](https://huggingface.co/datasets/alimamaTech/MAC)과 논문([arXiv 2603.02184](https://arxiv.org/abs/2603.02184))의 공식 모델 두 개(BASE, MoAE)로 이 문제를 다룹니다. 논문에서는 MoAE가 앞서지만, 마지막 두 학습 파일을 보정용으로 남긴 조건에서는 BASE가 순위와 희소 그룹의 확률 손실 모두에서 나았고 두 배 넘게 빨랐습니다. 그래서 BASE에 그룹별 축소 보정을 붙인 예측기를 만들었고, 이 예측기는 한 사용자의 광고 후보 100개를 CPU 코어 하나에서 수 ms 안에 점수화합니다.

## 주요 결과

- **공식 모델을 전체 학습 자료로 학습해 논문 표 4와 비교했습니다.** AUC와 GAUC 네 값이 모두 논문과 0.0032 안이고, 미리 정한 기준으로는 재현 1개, 근접 3개입니다. 그 과정에서 공식 실행 예제가 학습률 인자를 전달하지 못해, 의도한 0.004가 아니라 기본값 0.003으로 학습된다는 것을 찾았습니다.
- **확률 오차는 대부분 전체 수준의 문제였습니다.** 논문의 제안 모델(MoAE)은 전체 전환을 약 20%, 전환이 드문 그룹에서는 약 25% 적게 예측했습니다. 모든 클릭에 같은 보정을 하나 붙이자 O/E가 0.98, 0.99로 맞춰졌습니다. 그룹마다 보정을 따로 두는 방법은 그 위에 작지만 확인 가능한 이득을 더했습니다.
- **학습 파일을 두 개 더 쓰자 두 모델의 순위가 뒤집혔습니다.** `train-17`까지 학습하면 기준 모델(BASE)이 AUC에서 0.019 앞서고, `train-19`까지 학습하면 MoAE가 0.016 앞섭니다. 한 시점의 비교만으로 모델을 고르면 위험합니다.
- **보정 강도는 어떤 지표로 고르느냐에 따라 달라졌습니다.** 그룹 평균 LogLoss로 고르면 λ = 1, 그룹별 전환 합계로 고르면 λ = 10000이 뽑혔고, 앞의 선택은 그룹 합계 오차를 두 배 가까이 키웠습니다. 입찰은 클릭 한 건의 확률을, 성과 예측은 그룹 합계를 쓰므로 보정 후보는 실제로 쓸 곳의 지표로 함께 비교해야 합니다(LightGBM 백테스트).
- **후보 100개 요청을 CPU 코어 하나에서 p50 1.89ms, p99 3.21ms에 점수화합니다**(BASE, Linux 서버). V2 클릭으로 만든 합성 요청이고, 인코딩부터 보정까지의 시간입니다. 사용자 이력을 후보마다가 아니라 요청마다 한 번만 인코딩해서 p50을 34% 줄였고, 확률은 그대로입니다.

## 써 보기

```bash
uv sync
uv run python -m cvr.predictor examples/request.json
```

```json
{
  "model": "BASE",
  "calibration": "group-shrunk Platt on the ad group (ad_feat1)",
  "candidates": [
    {"ad_feat0": "bd06e0d08ba7", "ad_feat1": "707e766d45eb", "cvr": 0.0365, "cvr_uncalibrated": 0.0332},
    {"ad_feat0": "db402f022dcf", "ad_feat1": "76af7efae0d0", "cvr": 0.0133, "cvr_uncalibrated": 0.0177},
    {"ad_feat0": "ca752f48f687", "ad_feat1": "76dc15e364ed", "cvr": 0.0224, "cvr_uncalibrated": 0.0268}
  ],
  "values_not_in_vocabulary": {}
}
```

요청은 MAC의 원시 열(사용자 특성, 구매 이력, 후보별 광고 특성과 맥락 특성, 이력 상품별 유사도)로 씁니다. 구매 이력은 MAC처럼 20칸이고 빈 칸은 결측 토큰으로 채우며, 길이가 다르면 요청을 거부합니다. 어휘에 없는 값은 학습 때의 결측값으로 처리하고 응답에 개수를 돌려줍니다. `--jsonl`을 주면 모델을 한 번 띄운 채 한 줄에 요청 하나씩 받습니다.

[examples/model](examples/model)은 합성 자료로 공식 학습 코드를 돌려 만든 1.3MB짜리 예제라서 확률 값 자체는 의미가 없습니다. MAC으로 학습한 모델은 체크포인트가 2GB라 저장소에 넣지 않았습니다. 학습한 뒤에는 같은 명령에 모델 폴더와 어휘만 바꿔 씁니다.

```bash
python3 scripts/fetch_mac.py vocabs train/train-19.parquet     # 어휘(873MB)와 자료 한 파일
uv run python -m cvr.predictor export BASE_lr0.003_lam0.3_s2026 bundles/BASE_train17
uv run python -m cvr.predictor request-from data/raw/mac/train/train-19.parquet 123456 --candidates 100 > request.json   # 그 사용자의 클릭을 최대 100개
uv run python -m cvr.predictor request.json --bundle bundles/BASE_train17 --vocabs data/raw/mac/vocabs
```

학습 명령은 [docs/reproduce.md](docs/reproduce.md)에 있습니다. 보정기는 그것을 맞춘 체크포인트(`train-17`)에만 붙일 수 있습니다.

## 결과

따로 적지 않으면 공식 테스트(406만 클릭)에서 시드 3개를 평균한 값입니다. 구간은 사용자 단위 부트스트랩 95% 구간입니다.

### 재현 (논문 표 4)

| 모델 | AUC | 논문 | GAUC | 논문 |
|---|---|---|---|---|
| BASE | 0.8514 | 0.8494 | 0.7419 | 0.7424 |
| MoAE | 0.8674 | 0.8694 | 0.7604 | 0.7636 |

- 테스트 전에 차이 0.002 이내를 "재현", 0.005 이내를 "근접"으로 정했고, 재현 1개와 근접 3개가 나왔습니다. 두 AUC가 재현 기준을 넘은 양(0.0000091, 0.0000496)은 시드 표준편차(0.0020, 0.0010)보다 훨씬 작습니다.
- MoAE − BASE는 AUC +0.0159, GAUC +0.0186으로 논문(+0.0200, +0.0212)과 순서가 같습니다.
- 공식 `scripts/run.sh`는 `--learning_rate 4.0e-3`을 넘기지만 파서는 `--lr`만 알고, 모르는 인자는 `parse_known_args`로 조용히 버립니다. 그래서 예제는 기본값 0.003으로 학습됩니다. 이 저장소의 실행기는 모르는 인자를 오류로 처리하고, 학습률과 λ는 논문의 탐색 범위(MoAE 9 × 4, BASE 9)에서 검증 자료로 골랐습니다.

### 확률 (`train-17`까지 학습한 모델)

| 모델 | 보정 | 전체 O/E | 희소 그룹 O/E | 희소 그룹 LogLoss (그룹 평균) |
|---|---|---|---|---|
| MoAE | 없음 | 1.247 | 1.338 | 0.066216 |
| | 공통 | 0.976 | 0.987 | 0.064743 |
| | 그룹별 축소 | 0.986 | 0.988 | 0.064731 |
| BASE | 없음 | 1.118 | 1.139 | 0.062602 |
| | 공통 | 0.973 | 0.972 | 0.062493 |
| | 그룹별 축소 | 0.979 | 0.972 | 0.062482 |

- 희소 그룹의 과소 예측(1.338)은 대부분 전체 과소 예측(1.247)에서 왔습니다. 검증 자료에서도 전체 O/E가 1.245로 같았습니다.
- 그래서 공통 보정이 가장 큰 효과를 냈습니다(MoAE 희소 그룹 LogLoss −0.00147). 그룹별 축소 보정은 그 위에 −0.000011 [−0.000019, −0.000004]를 더했고, 시드 3쌍 모두 같은 방향이었습니다. 그룹별로 보면 548개가 좋아지고 431개가 나빠졌기 때문에, 실제로 쓴다면 그룹별 O/E를 지켜봐야 합니다.
- 학습할 때 희소 그룹에 가중치를 2배로 주는 방법은 효과를 확인하지 못했습니다(−0.000069 [−0.000231, +0.000088], 시드마다 방향이 다름).

### 어떤 모델을 쓰는가

| 학습 범위 | 보정 전 AUC (BASE / MoAE) | 그룹별 축소 보정 뒤 희소 그룹 LogLoss (BASE / MoAE) | 요청 p50 (BASE / MoAE) |
|---|---|---|---|
| `train-17`까지, 남은 두 파일로 보정 | 0.848 / 0.829 | 0.06248 / 0.06473 | 1.89 / 3.98ms |
| `train-19`까지 (모든 학습 파일) | 0.851 / 0.867 | 보정할 자료가 없어 평가하지 않음 | 구조가 같음 (재지 않음) |

보정까지 하려면 **BASE + 그룹별 축소 보정**을 권합니다. 검증 자료(V2)에서도 BASE가 AUC 0.849 대 0.847, 희소 그룹 LogLoss 0.06270 대 0.06294로 앞섰고, 두 배 넘게 빠릅니다. 모든 파일로 학습하면 MoAE가 순위에서 앞서지만, 확률 보정의 효과는 확인하지 못했습니다. 둘 중 어느 쪽이 나은지는 재학습 주기를 여러 기간에서 비교해야 정할 수 있습니다.

### 서빙 (Linux 서버, AMD EPYC 4565P 코어 하나)

| 모델 | 요청 p50 | 요청 p99 | 클릭 한 건 p50 | 공유 인코딩의 p50 단축 |
|---|---|---|---|---|
| BASE | 1.89ms | 3.21ms | 0.40ms | 34% |
| MoAE | 3.98ms | 5.64ms | 0.71ms | 20% |

- 요청은 사용자 1명과 후보 100개입니다. 20분 간격의 세 세션을 쟀고(세션마다 모델별 요청 6,000개), 표는 세 세션의 중앙값입니다. 모든 값이 세션 사이에서 1.16배 안이었습니다.
- 서빙한 확률은 평가 예측과 같은 배치 경로에서 2.1e-7 안으로 일치합니다. 한 행씩 계산하면 CPU에 따라 float32 반올림이 달라져 최대 1.8e-6까지 차이 납니다.
- 네트워크, 요청 파싱, 피처 저장소 조회는 시간에 넣지 않았습니다.

### 보정을 고르는 지표 (LightGBM, 작은 광고 맥락 그룹 22개, 백테스트)

| 강도를 고른 기준 | λ | 그룹 평균 LogLoss | 그룹 합계 deviance | 합산 O/E |
|---|---|---|---|---|
| 그룹 평균 LogLoss | 1 | 0.037947 | 3.755 | 0.950 |
| 그룹별 전환 합계 | 10000 | 0.038092 | 1.903 | 1.001 |

LogLoss로 고른 보정은 공통 보정보다 그룹 평균 LogLoss를 낮췄지만(−0.000147 [−0.000253, −0.000054]), 클릭 단위 LogLoss는 거의 그대로였고(−0.000003 [−0.000036, +0.000028]) 그룹별 전환 합계의 오차는 키웠습니다(Poisson deviance +1.80 [+0.41, +3.16]). 앞선 실험에서 이미 한 번 연 평가 자료를 다시 쓴 결과라 확증은 아닙니다([표](docs/results/study_d.md)).

자세한 표는 [공식 테스트](docs/results/e_final_test.md)와 [서빙](docs/results/e_serving.md)에, 원본 기록(JSON)은 [docs/results/records](docs/results/records)에 있습니다.

## 검증 방법과 한계

결과를 보기 전에 판정 기준을 적어 커밋했고([docs/DESIGN.md](docs/DESIGN.md)), 설정과 보정 강도는 검증 파일(V1, V2)에서만 골랐습니다. 모델, 보정기, 그룹 목록을 해시로 고정한 뒤 같은 평가 코드로 V2 값 407개를 1e-9 안에서 다시 계산했고, 그다음 질문마다 공식 테스트를 한 번만 열었습니다.

- 공식 테스트는 앞선 실험에서 다른 모델로 한 번 평가한 파일입니다. 그래서 결과는 "벤치마크 공식 테스트 기준"이고, 처음 보는 자료에서의 확증은 아닙니다.
- 전체 과소 예측의 원인(학습 기간과 평가일의 전환율 차이, 다중 과제 학습 등)은 분리하지 않았습니다.
- 순위 역전은 같은 학습 실행의 인접한 두 시점에서 본 것이라 독립된 반복이 아닙니다.
- MAC에는 지출과 경매 정보가 없어서 입찰 성과나 CPA는 다루지 않았습니다.
